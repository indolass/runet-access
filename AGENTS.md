# Правила работы над runet-access

## Единственная рабочая папка Windows

Owner закрепил корень: `D:\AI-workspaces\runet-access`.
Репозиторий: https://github.com/indolass/runet-access.

Все создаваемые агентом рабочие каталоги, исходники, сторонние checkout,
скачивания, инструменты, кэши, временные файлы, сборки, логи, профили тестового
браузера и отчёты должны находиться строго внутри этого корня.
Не создавать соседние папки, дополнительные workspace или worktree вне корня.
Не использовать junction/symlink для обхода этого ограничения.

Минимальная структура (создавать только по необходимости):
- src/ — поддерживаемый код проекта;
- docs/ — документация;
- scripts/ — сборка и запуск;
- .local/upstream/MagicProxy/ — исходники для изучения;
- .local/tools/ — переносимые инструменты;
- .local/cache/ — кэши;
- .local/tmp/ — временные файлы;
- .local/browser-profile/ — отдельный тестовый профиль;
- .local/logs/ — локальные логи без секретов;
- dist/ — результаты сборки.

Перед сборкой перенаправить в корень настройки инструментов: TEMP, TMP,
GOPATH, GOCACHE, GOMODCACHE, GOTMPDIR и применимые кэши других менеджеров.
Не переопределять HOME, USERPROFILE или CODEX_HOME.
Предпочитать переносимые инструменты; не менять глобальный PATH.
Проверить фактические пути кэшей, а не только объявить переменные.

Это правило регулирует файлы проекта, создаваемые и направляемые агентом.
ОС, уже установленный браузер и сама среда Claude могут иметь собственные
служебные записи вне проекта. Не обещать полную изоляцию таких записей.
Если сборке или установке нужны управляемые агентом записи вне корня,
сначала предложить локальный вариант; если его нет — описать точные пути
и согласовать исключение. Самовольно глобально ничего не устанавливать.

## Перенос предыдущего checkout

По предоставленному отчёту Claude исходники находятся в
`D:\AI-workspaces\MagicProxy_GovSite\upstream`.
Локальное состояние ещё не проверено.

1. Прочитать применимые родительские инструкции. Проверить оба пути,
   Git remote, HEAD, status и наличие пользовательских файлов.
2. Подготовить основной checkout runet-access в утверждённом корне.
   Не клонировать поверх существующих файлов.
3. Переместить существующий upstream в .local/upstream/MagicProxy,
   сохранив его Git-историю и локальные изменения. Не перезаписывать
   существующее назначение. При конфликте сначала сравнить.
4. Проверить HEAD, status и сохранность файлов после переноса.
5. Старую папку MagicProxy_GovSite удалить только если она действительно
   пуста, без рекурсивного удаления. Если что-либо осталось — сообщить.
6. Не коммитить вложенный checkout как случайный gitlink.

## Задача и границы

Сценарий: человек без технических навыков открывает приложение/браузер,
вставляет ключ из Telegram, подключается и вручную работает с нужным сайтом.
Приоритет — повторное использование готового проекта.
MagicProxy — кандидат; архитектурное решение принять после проверки кода.

Не менять системный прокси, сетевые адаптеры, DNS Windows и TUN.
Использовать отдельный профиль браузера. Обычный интернет остальных
программ и профилей должен продолжать работать.
Не автоматизировать вход в государственный кабинет, подпись и отправку отчётов.

Реальные ключи, UUID доступа, конфиги, cookies и персональные данные
не публиковать в Git, логах, скриншотах, issues или отчётах.
Реальный ключ Owner вводит локально. Тесты используют синтетические данные.
.gitignore не заменяет проверку staged diff перед коммитом.

Непроверенные бинарники из upstream не запускать.
Зависимости брать из официальных источников, фиксировать версии, источник
и доступные проверки целостности. Проверять лицензии по закреплённым версиям.
MIT проекта не заменяет лицензии сторонних компонентов.

Не утверждать «подключено к России» только по запуску процесса.
Проверять выход через тот же маршрут, которым пользуется целевой сайт.
При PAC диагностические домены тоже должны идти через прокси.
Проверить сбой ядра: целевые запросы не должны незаметно уходить напрямую.

Разрешены необходимые загрузки переносимых инструментов, локальная сборка
и тесты внутри корня для согласованного прототипа.
Установка в обычный профиль Chrome, изменение реестра и глобальная
установка инструментов требуют отдельного согласования точных изменений.

В конце сообщать: что сделано, результаты проверок, оставшиеся препятствия,
commit SHA и совпадение remote, если публикация выполнялась.
