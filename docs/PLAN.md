# Первый прототип

## Цель

Windows 11: вставить ключ VLESS из Telegram → подключиться → увидеть
результат проверки российского выхода → открыть нужный сайт.
Пользователь не настраивает порты, PAC и системный прокси вручную.
Ключ и доступный российский сервер предоставляет сторонний оператор:
приложение само не создаёт российский выход и не гарантирует его доступность.

## Исходное состояние

Репозиторий создан Owner. Работающий прототип в нём ещё не опубликован.
По отчёту локального Claude изучены MagicProxy и Noctis, исходники
MagicProxy клонированы вне утверждённого корня. Этот checkout нужно перенести.

Отчёт считает MagicProxy подходящей основой: расширение, native messaging,
локальное ядро, импорт VLESS Reality и маршрутизация выбранных доменов.
Версии, лицензии, обработка ошибок, fail-closed, хранение ключа и содержимое
бинарников из этого отчёта требуют проверки по конкретному upstream SHA.
Отчёт не является подтверждением работающего соединения или аудита безопасности.

## Этапы

1. Привести рабочие каталоги к AGENTS.md, получить актуальный main.
2. Зафиксировать SHA MagicProxy, изучить лицензию и зависимости, парсер,
   native host, установщик, хранение секретов и сетевые настройки.
   Существующие полезные результаты исследования сохранить, не повторять
   исследование без причины. Noctis оставить сравнительным кандидатом.
3. Переносимыми инструментами собрать проверенный исходный код.
   Не запускать подозрительный vendor-bin/magicproxy-host.exe~.
   Для начала использовать тестовую конфигурацию без действующих секретов.
4. Реализовать минимальный интерфейс: вставка/замена ключа, подключение,
   проверка выхода, открытие URL, отключение и понятная ошибка.
   Технические параметры скрыть от основного пользовательского сценария.
5. Проверить маршрут проверки IP, переходы авторизации, сбои и отключение.
6. Дать Owner короткие шаги ручной проверки реального ключа и сайта.
7. Подготовить пакет для чистого Windows-профиля, инструкцию и ограничения.
   Выпуск публичного релиза — после проверки установки.

## Открытые вопросы, не блокирующие локальную сборку

Точный домен, цепочка авторизации и требования к электронной подписи
пока не указаны. URL сделать настраиваемым; не выдумывать адрес портала.
Совместимость с подписью и полную подачу отчёта считать непроверенными.

Выбор доставки расширения/приложения ещё не принят. Ручная загрузка
распакованного расширения допустима для инженерной проверки, но не
соответствует конечной цели plug-and-play.
Проверить варианты упаковки, требования браузера, предупреждения
установщика и процедуру обновлений. Не предполагать, что Setup.exe
автоматически разрешает установку произвольного расширения в Chrome.

## Приёмка

- Весь управляемый рабочий материал находится в утверждённом корне.
- Импорт синтетического VLESS Reality/vision ключа корректен;
  неправильный ключ даёт понятную ошибку без раскрытия его содержимого.
- Системный прокси/TUN не меняются; обычный профиль браузера работает.
- Проверка IP идёт через выбранный сервер. Сбой диагностики отображается
  как неопределённый результат, а не как успешное подключение.
- При остановке ядра целевой сайт не переключается незаметно на прямой выход.
- Повторный запуск и отключение не оставляют забытых процессов и конфигов.
- Реальный ключ и данные кабинета отсутствуют в staged diff и отчётах.
- Российский выход, вход на конкретный сайт и электронная подпись
  отмечены отдельно: PASS / FAIL / NOT TESTED с наблюдаемым результатом.
- Установка человеком без технических навыков проверена отдельно.
  До этого результат называется прототипом.
