# Установщик Runet Access

Один файл `RunetAccess-Setup-<версия>.exe` (Inno Setup 6.7.3), который можно передать другому человеку.
Результат сборки лежит в `dist\installer\` (в Git не входит: `dist/` и `*.exe` в `.gitignore`).

## Состав

Только то, что перечислено в `scripts\make-installer.ps1` (staging `dist\installer-staging\app` собирается по явному списку и
сверяется с ним; лишний файл останавливает сборку):

| Файл в папке программы | Откуда |
|---|---|
| `RunetAccess.exe` | свежая сборка `scripts\build.ps1` (проверяется, что файл новее начала запуска) |
| `sing-box.exe` | неизменённый официальный выпуск v1.13.16; перед упаковкой заново извлекается из закреплённого zip, хеши сверяются |
| `Инструкция.txt` | `installer\` — короткая инструкция по-русски |
| `BUILD-INFO.txt` | коммит Git, дата, версии Go, sing-box, Inno Setup, пометка «не подписано» |
| `licenses\LICENSE.txt`, `THIRD_PARTY.txt` | MIT проекта и перечень сторонних компонентов |
| `licenses\MagicProxy\`, `licenses\Go\` | лицензии MagicProxy (MIT) и Go (BSD-3-Clause, стандартная библиотека входит в `RunetAccess.exe`) |
| `licenses\sing-box\` | `GPL-3.0.txt`, `LICENSE`, `SOURCE-OFFER.txt`, `SOURCE-INFO.txt`, `sing-box-1.13.16-source.tar.gz` |

Не входят: инструменты сборки, тесты, `.local`, ключи и подписочные ссылки, сохранённые DPAPI-файлы, профили Chrome, cookies,
история, логи, снимки, любые конфиги. Перед компиляцией staging проверяется на: недопустимые типы файлов, URI вида
`vless://<uuid>@…`, и **отпечатки ключа Owner** (UUID и адрес сервера из `.local\secrets\test-key.txt` ищутся в каждом файле;
значения не печатаются).

Рядом с `Setup.exe` скрипт пишет `*.contents.txt` (путь, размер, SHA-256 каждого устанавливаемого файла),
`*.build-info.json` (хеш установщика, коммит Git, `gitDirty`, версии компонентов, статус подписи) и `SHA256SUMS.txt`.

## Параметры установки

- для текущего пользователя, без запроса прав администратора (`PrivilegesRequired=lowest`, переключение режима отключено;
  манифест `RunetAccess.exe` — `asInvoker`);
- русский мастер, стабильный `AppId` `{B7E2C1A4-5D3F-4E8B-9A16-0C4D7F2E6A31}`, версия из файла `VERSION`;
- папка по умолчанию `%LOCALAPPDATA%\Programs\RunetAccess`; ярлык в «Пуске», ярлык на рабочем столе по выбору (по умолчанию
  выключен), предложение запустить программу, удаление через «Приложения»;
- нет автозапуска, служб, заданий планировщика, правок системного прокси, сети, ассоциаций браузера;
- запущенную программу установщик и деинсталлятор обнаруживают по мьютексу (`AppMutex`), просят закрыть и ждут; принудительного
  закрытия и Restart Manager нет (`CloseApplications=no`).

## Данные пользователя

Установленные файлы, данные пользователя и временные файлы разделены (см. таблицу в [INSTALL.md](INSTALL.md)):
программа живёт в `%LOCALAPPDATA%\Programs\RunetAccess`, ключ (`key.dpapi`) и профиль (`profile`) — в
`%LOCALAPPDATA%\RunetAccess`. Эти пути были такими и до установщика, поэтому **перенос данных не потребовался**: старые данные
запуска из папки `dist` сразу подхватываются установленной копией.

При удалении неинтерактивно данные остаются (удалить: `/DELETEDATA`); интерактивно задаётся вопрос с ответом «Нет» по умолчанию.
Удаляются только поимённо: `key.dpapi`, `key.dpapi.tmp`, `run.lock`, папка `profile`, затем сама папка данных, если она стала
пустой (`RemoveDir` не удаляет непустую). Путь обязан оканчиваться на `RunetAccess`. Обычный профиль Chrome и всё вне этой папки не
затрагиваются.

## Chrome

Свою копию браузера мы не поставляем. Chrome ищется в `Program Files`, `Program Files (x86)`, `%LOCALAPPDATA%` и по ключам
«App Paths» (пользовательский и машинный, только чтение реестра). Если не найден, **до запуска ядра и страницы управления**
показывается короткое окно «Нужен Google Chrome» с командами:

- **«Скачать и установить Chrome»** (по умолчанию). Программа скачивает официальный установщик Google
  (`https://dl.google.com/tag/s/…/ChromeSetup.exe`, 64-бит, стабильная ветка, отправка статистики по умолчанию выключена),
  затем **Windows проверяет цифровую подпись**: подпись обязана быть действительной, цепочка — доверенной, отзыв проверяется,
  издатель — «Google LLC». Только после этого установщик запускается **как есть, без параметров** (никакой тихой установки,
  никакого скрытого принятия условий Google), с обычным запросом Windows (UAC), который подтверждает пользователь.
  Потом Chrome ищется снова (до 3 минут ожидания) и программа продолжает работу сама.
- **«Открыть страницу Chrome (вручную)»** — запасной вариант: официальная страница Google, открывается только по нажатию.
- **«Проверить снова»** и **«Закрыть»** (закрытие завершает программу без ошибки).

Что гарантируется кодом (`chrome_install.go`, тесты в `chrome_install_test.go`):

- загрузка только с хоста `dl.google.com` по HTTPS; каждый редирект проверяется тем же правилом; адреса с логином и паролем,
  чужие хосты и обычный HTTP отвергаются до обращения к сети;
- файл должен быть программой Windows (`MZ`), не страницей и не больше 300 МБ; во временной папке `%TEMP%\runet-access\chrome-setup-*`;
- файл **не подписанный Google или с изменённым содержимым не запускается** и удаляется; проверка подписи не отключается и не
  ослабляется;
- уже установленный Chrome **не переустанавливается** (поиск выполняется до загрузки и перед запуском; если Chrome появился во
  время загрузки, установщик не запускается), его профиль и настройки не затрагиваются;
- отмена, отказ в запросе Windows и ошибка загрузки дают короткое понятное сообщение и возможность повторить; запущенный
  установщик при отмене ожидания не завершается принудительно.

Технические подробности последней попытки (источник, конечный адрес, ответ сервера, тип содержимого, размер, SHA-256,
издатель подписи, результат проверки) лежат в раскрываемом разделе «Подробности» окна и не перегружают основной текст.
Chrome не становится браузером по умолчанию, обычный профиль для рабочих сайтов не используется (всегда отдельный `--user-data-dir`).

Тестовые окна (когда включена любая тестовая подмена: `RUNET_CHROME_PATH`, `RUNET_TEST_CHROME_URL`, `RUNET_TEST_CHROME_PROMPT`,
`RUNET_TEST_DIALOG_DUMP`) в заголовке и тексте помечены **«ТЕСТ»**, чтобы их нельзя было принять за реальную ошибку. Автоматические
проверки окон запускаются на скрытом рабочем столе Windows (`tests\run-hidden.ps1`), на экране пользователя они не появляются.

## Подпись

Установщик и программы **не подписаны** (сертификат не покупался). Следствия: SmartScreen и некоторые антивирусы могут
показать предупреждение или заблокировать запуск; репутации у файла нет. Получатель должен получить SHA-256 установщика по другому
каналу, чем сам файл, и сверить его. SmartScreen и антивирус мы не отключаем и отключать не предлагаем.

## Лицензии и исходный код

- **sing-box (GPL-3.0-or-later)** поставляется без изменений вместе с текстом лицензии, архивом исходников точной версии
  (`licenses\sing-box\sing-box-1.13.16-source.tar.gz`, SHA-256 закреплён в `tools.lock.json`) и письменным предложением на
  исходники зависимостей (GPLv3 §6b). Зависимости (≈1,6 ГБ) в установщик не кладутся; полный комплект собирает
  `scripts\make-source-offer.ps1` в `dist\source-offer\` (≈440 МБ) для выполнения запросов. Это **наша трактовка** требований
  GPL (исходники самого компонента приложены, остальное — по предложению); юридической экспертизы не проводилось.
- `RunetAccess.exe` — наш код (MIT) на базе пакетов MagicProxy (MIT) и стандартной библиотеки Go (BSD-3-Clause); тексты лицензий
  поставляются. Программа запускает sing-box отдельным процессом.
- Inno Setup — только компилятор. Он скачан с официального GitHub-релиза `jrsoftware/issrc`, SHA-256 сверен со значением
  релиза, подпись Authenticode `Pyrsys B.V.` действительна; версия и хеши файлов компилятора закреплены в `tools.lock.json`.
  Inno Setup сам пишет в `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\Inno Setup 6_is1` (его собственная запись для списка
  приложений; файлы лежат в `.local\tools\innosetup`); при желании её можно удалить вместе с папкой.

## Проверки

`tests\installer-check.ps1` — установка, запуск, обновление и удаление настоящего установщика (см. результаты в
[LIMITATIONS.md](LIMITATIONS.md)). Проверка на чистой Windows **не проводилась**: Windows Sandbox недоступна на Windows 11 Home,
виртуальных машин нет, устанавливать гипервизор или включать компоненты без отдельного согласования нельзя.
