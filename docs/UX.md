# Интерфейс специального браузера (UI/UX)

Согласовано с Owner 2026-10-06. Реализовано в `src/app/cmd/launcher/ui/` (HTML, CSS, JS без фреймворков) и
`src/app/cmd/launcher/` (Go). Проверяется сквозным тестом `tests\launcher-e2e.mjs` в настоящем Chrome.

## Пользовательский сценарий

1. **Первый запуск.** Заголовок «Российские сайты — в отдельном окне», пояснение «Подключение действует только в этом
   браузере». Поле «Ключ подключения» (принимает `vless://`, `ss://`, `ssconf://`; формат определяется сам), флажок «Запомнить на этом
   компьютере», кнопка «Подключиться», раскрывающийся блок «Нет ключа?».
2. **«Нет ключа?»** Короткая инструкция из четырёх шагов и два источника: «Назад в СССР» (`t.me/BackInTheUSSR_bot`) и
   «HLVPN» (`t.me/hlvpnbot`, в боте «Подключиться → Рунет»). У каждого — «Открыть» и «Скопировать ссылку». Работает **до**
   подключения. Мы не обещаем бесплатность, работоспособность любого ключа или отсутствие капчи.
3. **Главный экран.** Вверху компактный статус («Подключено через Россию», рядом «Отключиться»). Ниже плитки Госуслуги,
   Налоговая, Минюст и поле «Другой сайт» с кнопкой «Открыть». Сайты открываются в **соседних вкладках** этого же браузера.
   Подробности (IP и страна выхода, обычный IP, повторная проверка, безопасные сведения) — в сворачиваемом блоке.
4. **Повторный запуск.** Сохранённый ключ повторно не запрашивается. Показаны сайты и «Подключиться». Сам по себе ничего не
   подключается. Нажатие на плитку = подключение → проверка российского выхода → открытие выбранного сайта, ровно один раз.
5. **Настройки.** «Заменить ключ» (с «Проверить и сохранить» и «Отмена»), «Удалить сохранённый ключ» (с подтверждением),
   пояснение о локальном хранении.
6. Внизу: «Спасибо за помощь с подключением — Ускоритель WWW» (канал помогавшего человека, **не** служба поддержки) и
   «Скопировать ссылку».

## Состояния и действия

| Состояние | Текст | Действия |
|---|---|---|
| не подключено | Не подключено | Подключиться |
| соединяемся | Подключаемся… | Отмена |
| проверка | Проверяем подключение через Россию… | Отмена |
| готово | **Подключено через Россию** | Отключиться |
| сервер не отвечает | Сервер недоступен | Повторить, Заменить ключ |
| формат ключа | Неверный или неподдерживаемый формат ключа (под полем) | править ключ |
| страна не подтверждена | Не удалось подтвердить страну выхода | Повторить проверку, Отключиться |
| выход не в России | Выход не в России (страна из проверки) | Повторить, Заменить ключ |
| трафик мимо ключа | Трафик идёт мимо ключа | Повторить, Заменить ключ |
| разрыв | Соединение прервано | Повторить, Заменить ключ |

Различия не косметические: «Сервер недоступен» ставится только когда TCP-порт сервера действительно не отвечает.
Если сервер отвечает, а сервис определения страны молчит, пишется «Не удалось подтвердить страну выхода» с пояснением, что
это не значит, будто ключ неисправен. Статус всегда описан словами, не только цветом.

## Правила, которые держит код

- **Поле ключа — обычное `textarea` без обработчиков paste/beforeinput, без `maxlength`, никогда не `disabled`/`readOnly`.** Текст
  в нём меняет только пользователь: периодическая перерисовка его не трогает, после любой ошибки он остаётся для правки, очищается
  он один раз, когда лаунчер принял ключ. Слишком длинный текст (больше 8 192 знаков, то есть вставлено целое сообщение) отклоняется
  до разбора с подсказкой «скопируйте только сам ключ». Проверяется настоящим вводом в настоящем Chrome: `tests\input-check.ps1`
  (реальный клик, клавиши, Ctrl+V и Shift+Insert из системного буфера на отдельной window station).
- **Ключ сохраняется только после успешной проверки выхода** (`app.verdict` в `main.go`). Новый ключ, не прошедший проверку,
  не затирает прежний сохранённый. Тест: `settings: FAILED replacement…` сравнивает хеш файла ключа.
- **Замена ключа.** Ключ неверной формы отклоняется до любых изменений (прежнее подключение остаётся). Правильный по форме
  ключ останавливает прежнее соединение и пробуется как новый: прежнее соединение не может сойти за подключение новым ключом.
  Неудача оставляет сохранённый ключ нетронутым и предлагает «Повторить» (возврат к сохранённому).
- **Устаревший зелёный статус невозможен.** Каждый запуск ядра — новая «эпоха». При аварийном перезапуске ядра подтверждение
  сбрасывается сразу, запоздалый вердикт старой проверки игнорируется, проверка выхода идёт заново. Периодическая проверка
  (раз в минуту) снимает зелёный статус, если выход перестал подтверждаться.
- **Одна операция за раз и корректная отмена.** У каждой операции номер; «Отмена» и «Отключиться» делают её устаревшей, её
  результат отбрасывается (в том числе у сервера: подключение, начатое до отмены, гасит ядро). Все сетевые вызовы ограничены
  по времени, состояние «занято» не может зависнуть.
- **Сайт открывается один раз и только после подтверждённого выхода.** Повторные клики во время ожидания игнорируются; при
  ошибке или отмене ожидающее открытие снимается.

## Почему вкладки открывает лаунчер, а не `window.open`

Измерено в настоящем Chrome (шаг `DOCUMENTED FACT` в e2e): `window.open()`, вызванный через 7 секунд после реального клика,
**блокируется** как всплывающее окно. Подключение и проверка выхода занимают дольше, поэтому вариант «открыть из страницы после
асинхронной проверки» не работает. Вместо него лаунчер (`/api/open-site`) повторно запускает Chrome с тем же профилем и теми же
ключами прокси и адресом сайта: Chrome передаёт адрес уже работающему окну и открывает новую вкладку. Даже если окно только что
закрылось, новый экземпляр тоже идёт через прокси (без прямого выхода). Вызов принимает только http/https-адрес внешнего хоста
и только после подтверждённого выхода.

## Внешние ссылки помощи (до подключения)

До подключения окно браузера не выходит в интернет вообще (так задумано), поэтому ссылки открывает Windows в **обычном**
браузере или в Telegram. Страница передаёт лаунчеру только идентификатор из фиксированного списка из трёх записей
(`externalLinks` в `main.go`); произвольных адресов или команд endpoint не принимает. Запуск — `ShellExecuteW` с одним
параметром, без оболочки и без подстановки в командную строку. Защита локального API сохранена: случайный токен-cookie,
проверка `Host`, обязательный заголовок `X-Runet` и метод POST для любых изменяющих вызовов (теперь и для `disconnect`/`forget`).
Копирование ссылки — только по нажатию пользователя; фонового чтения буфера и автоподстановки ключей нет.

## Внешний вид

Светлая тема и тёмная (автоматически), синий акцент, крупный шрифт, плитки сайтов, видимый контур клавиатурного фокуса,
цели нажатия не меньше 44 px. Проверено на окне 1280×720 при 125% и 150%, на ширине 360 px (нет горизонтальной прокрутки),
в тёмной теме. Снимки: [screenshots/](screenshots/).
