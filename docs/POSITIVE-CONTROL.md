# Положительный контроль на публичных серверах (2026-10-03)

Цель: доказать, что связка «ключ → наш парсер → наш генератор → sing-box → браузер» работает против **внешнего**
сервера, независимо от того, как поведёт себя ключ владельца. Российский выход и госсайты здесь **не** проверялись:
это следующий этап.

## Источник и отбор

Публичный список проверенных VLESS-ключей <https://tiagorrg.github.io/vless-checker/> (данные в
<https://github.com/tiagorrg/vless-checker>, MIT; обновляется раз в 30 минут). Проверка TCP на их сайте
работоспособность туннеля **не** доказывает, поэтому каждый ключ проверялся здесь заново.

Из 218 ключей совместимы с прототипом (VLESS + Reality + TCP + `xtls-rprx-vision`) 114, но это всего 20 уникальных
серверов. Отобрано 5 разных серверов. Ключи, адреса и конфигурации лежат только в `.local\data\` (исключено из Git).

## Критерий успеха

`https://example.com/` загружен **через** локальный прокси с **включённой** проверкой TLS-сертификата
(curl/Schannel, `ssl_verify_result = 0`), HTTP 200, на странице ожидаемый текст. Открытый порт и запущенный процесс
успехом не считались. Запросы ограничены по времени, ходили только публичные тестовые страницы.

Совпадение по всем пяти: что работает в независимом Xray, работает и в нашем коде. Расхождений не найдено,
исправлять нечего.

### Браузерная часть на c1 (через `RunetAccess.exe` и настоящий Chrome)

- **Штатные правила (нужна RU):** приложение **отказало по стране** («Выход не в нужной стране: NL (нужна RU)»),
  отключилось, окно осталось отрезанным от интернета. Это отказ по стране, а не ошибка соединения.
- **Тест-режим** `RUNET_EXPECTED_COUNTRY=NL` (проверка страны остаётся настоящей: реальный сервис страны через
  туннель и сравнение с обычным адресом; значение по умолчанию `RU` не менялось): подключено, выход NL подтверждён,
  адрес выхода отличается от обычного. В браузере открылись публичные страницы `example.com` (https, видимое
  содержимое, без ошибки сертификата) и `api.country.is`. После «Отключить» окно снова отрезано от интернета.
- После закрытия окна лаунчер завершился, процессов и блокировки не осталось. Системный прокси не менялся.

## Что подтверждено и что нет

Подтверждено: транспорт нашего кода работает с внешними серверами (5 из 5); браузерная часть, отказ по стране и
fail-closed работают на одном внешнем сервере; с этого компьютера и соединения VLESS+Reality работает (TCP до
публичных серверов открывается за десятки миллисекунд). Следовательно, отказ сервера из ключа владельца
**специфичен для того сервера или маршрута до него**, а не для компьютера или провайдера в целом. Различить «сервер
выключен» и «маршрут режется» по-прежнему нельзя.

Не подтверждено: российская страна выхода; доступ к Госуслугам, ФНС, Минюсту; браузер на кандидатах c2–c5;
длительная стабильность; электронная подпись; установка неподготовленным пользователем.

## Оговорки

- Публичные серверы чужие и недоверенные: их операторы видят трафик. Через них ходили только публичные тестовые
  страницы, без входа в аккаунты. Для рабочих задач это не подходит.
- Список меняется, серверы живут недолго: результат справедлив на момент проверки.
- Задержки на сайте источника измерены из США и для этого компьютера ничего не значат.
- Независимый Xray взят из установленного у владельца v2rayN (копия `xray.exe` в `.local\tools`, версия 26.9.9);
  запускался напрямую через CLI, без GUI, буфера обмена и имитации ввода.

## Как повторить

```powershell
. .\scripts\env.ps1
curl.exe -sS -o .local\data\keys.json https://tiagorrg.github.io/vless-checker/keys.json
node tests\public-select.mjs 5          # отбор; полные ключи только в .local\data\selected.json
node tests\public-xray-check.mjs        # независимый Xray
go build -o .local\tools\buildcfg.exe .\cmd\buildcfg   # из src\app
node tests\public-singbox-check.mjs     # наш парсер + генератор + sing-box
node tests\public-browser-check.mjs     # лаунчер + Chrome (нужен scripts\build.ps1)
```
