# Установка Runet Access (прототип)

> Это инженерный прототип, **не plug-and-play**. Установка человеком без технических навыков
> ещё не проверялась (см. [LIMITATIONS.md](LIMITATIONS.md)). Нужен Windows 11 и Google Chrome.

## Что устанавливается

- Расширение для Chrome (окно «Runet Access»).
- Небольшая программа-помощник и ядро sing-box: запускаются самим Chrome, пока подключение включено.
- Одно значение реестра текущего пользователя, чтобы Chrome нашёл помощника. Права администратора не нужны.
- Не меняются: системный прокси Windows, сетевые адаптеры, DNS, TUN, другие программы и браузеры.

## Шаги

1. Распакуйте папку `runet-access` в постоянное место (например, `C:\Users\<имя>\RunetAccess`).
   Не запускайте из «Загрузок» или временной папки. Если папку переместить, повторите шаг 2.
2. Дважды щёлкните **Install.cmd**. Если Windows показала «Защитник Windows SmartScreen» —
   «Подробнее» → «Выполнить в любом случае» (файлы не подписаны, см. ограничения).
3. Создайте отдельный профиль Chrome (значок профиля → «Добавить» → «Продолжить без аккаунта»).
4. В этом профиле: адрес `chrome://extensions` → включить «Режим разработчика» → «Загрузить
   распакованное» → выбрать папку `extension` внутри `runet-access` → закрепить значок расширения.
5. Нажмите на значок: «Настройки сайта» → адрес сайта → «Сохранить». Вставьте ключ → «Подключить».

Короткая проверка с реальным ключом: [MANUAL-CHECK.md](MANUAL-CHECK.md).

## Удаление

**Uninstall.cmd**, затем удалить расширение в `chrome://extensions` и папку программы.

## Сборка из исходников (для разработчиков)

```powershell
.\scripts\build.ps1                 # докачивает Go и sing-box в .local\tools (по закреплённым хешам),
                                    # гоняет тесты, собирает dist\runet-access
node tests\host-e2e.mjs             # хост + ядро против синтетического Reality-сервера (после env.ps1)
.\scripts\run-browser-e2e.ps1       # сквозной тест в Chrome; на время теста пишет и удаляет ключ реестра
```

Все кэши, инструменты, временные файлы и профили тестового браузера лежат внутри корня проекта
(`scripts\env.ps1`). Тестовый Chrome запускается с отдельным профилем в `.local\browser-profile`.
Chrome 137+ игнорирует `--load-extension`, поэтому тесты грузят расширение через
`Extensions.loadUnpacked` по отладочному каналу `--remote-debugging-pipe`.
