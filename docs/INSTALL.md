# Установка и запуск Runet Access (прототип)

> Прототип, **не проверенный на чистой Windows и неподготовленным пользователем** (см. [LIMITATIONS.md](LIMITATIONS.md) и
> [INSTALLER.md](INSTALLER.md)). Нужны Windows 10 или 11 (64-бит) и установленный Google Chrome.

## Для пользователя: установка из RunetAccess-Setup.exe

Python, Go, Node.js, Git, терминал и права администратора **не нужны**.

1. Запустите `RunetAccess-Setup-<версия>.exe`. Файл **не подписан** цифровой подписью, поэтому Windows может показать
   предупреждение SmartScreen: «Подробнее» → «Выполнить в любом случае» (только для файла от человека, которому вы
   доверяете; файл можно сверить по SHA-256, который вам сообщили).
2. Мастер на русском языке. Папка по умолчанию `%LOCALAPPDATA%\Programs\RunetAccess` (в вашей учётной записи). Ярлык в меню
   «Пуск» создаётся всегда, ярлык на рабочем столе — по галочке.
3. В конце можно сразу запустить программу. Если Chrome не установлен, программа покажет небольшое окно: «Скачать и установить Chrome»
   (официальный установщик Google, подпись проверяется до запуска, окна и вопросы Windows вы подтверждаете сами),
   «Открыть страницу Chrome (вручную)», «Проверить снова», «Закрыть». Установленный Chrome не трогается и не переустанавливается.
4. Первый запуск: в окне программы раскройте «Нет ключа?», откройте одного из ботов (ссылки работают до подключения), получите
   ключ (строка `vless://…`), вставьте в поле «Ключ подключения» и нажмите «Подключиться». Короткая инструкция лежит в папке
   программы (`Инструкция.txt`) и в меню «Пуск».

**Обновление.** Запустите новый установщик: он заменит программу в той же папке, не создаст второй записи в «Приложениях» и
второго ярлыка. Ключ и профиль браузера лежат в другой папке и не затрагиваются.

**Если программа запущена,** установщик попросит её закрыть и подождёт. Он ничего не завершает принудительно и Chrome не трогает.

**Удаление:** «Параметры» → «Приложения» → Runet Access → «Удалить». Программа и её ярлыки удаляются. Затем задаётся отдельный
вопрос: удалить ли сохранённый ключ и профиль специального браузера (по умолчанию **нет**). Обычный профиль Chrome и любые
данные вне папки `%LOCALAPPDATA%\RunetAccess` не затрагиваются никогда.

## Где что лежит

| Что | Где | Кто управляет |
|---|---|---|
| Программа: `RunetAccess.exe`, `sing-box.exe`, лицензии, инструкция | `%LOCALAPPDATA%\Programs\RunetAccess` | установщик (обновляет и удаляет) |
| Сохранённый ключ (зашифрован Windows DPAPI), профиль специального браузера (`profile`) | `%LOCALAPPDATA%\RunetAccess` | программа; установщик не трогает, удаляет только по явному ответу |
| Временный конфиг запуска ядра | `%TEMP%\runet-access\host-<PID>` | программа; удаляется сразу после старта ядра и при выходе |

В реестре установщик делает только обычную запись для списка «Приложения» (`HKCU\...\Uninstall`). Он не меняет системный
прокси, сетевые параметры, браузер по умолчанию и не добавляет автозапуск, службы и задания планировщика. Сама программа в
реестр не пишет (читает только путь Chrome).

## Как это устроено

Один запуск = одно специальное окно Chrome. `RunetAccess.exe` запускает ядро sing-box на `127.0.0.1` и отдельный Chrome со
своим профилем, весь трафик которого идёт через ваш ключ. Ничего не устанавливается в систему: нет расширений, режима
разработчика, системного прокси, TUN, служб. Обычный Chrome и другие программы работают как раньше. Закрыли окно — ядро
остановлено, конфиг с ключом удалён.

## Запуск без установщика (из папки dist)

`dist\runet-access\RunetAccess.exe` запускается двойным щелчком так же, как установленная копия, и пользуется теми же данными
пользователя.

## Сборка из исходников (для разработчиков)

```powershell
.\scripts\build.ps1                 # докачивает Go и sing-box в .local\tools (по закреплённым хешам),
                                    # гоняет тесты, собирает dist\runet-access
.\scripts\make-installer.ps1        # то же + проверка происхождения компонентов, staging по явному списку,
                                    # проверка на секреты, dist\installer\RunetAccess-Setup-<версия>.exe
. .\scripts\env.ps1; node tests\launcher-e2e.mjs      # сквозной тест в настоящем Chrome (36 шагов)
.\tests\installer-check.ps1         # установка/обновление/удаление настоящего установщика в изолированных папках
```

Все кэши, инструменты, временные файлы и профили тестов лежат внутри корня проекта (`scripts\env.ps1`). Тест запускает
лаунчер с `RUNET_ACCESS_HOME` внутри корня и синтетическим сервером на localhost.

Переменные окружения лаунчера (только для тестов). **Все, кроме `RUNET_ACCESS_HOME` и `RUNET_NO_DIALOG`, игнорируются, пока не задан
`RUNET_TEST_MODE=1`**, поэтому оставшаяся в среде переменная не может повлиять на обычный запуск: `RUNET_CHROME_PATH`,
`RUNET_CHROME_EXTRA_ARGS`, `RUNET_PROBE_URL` (подмена адреса проверки страны), `RUNET_OPEN_LOG` (файл вместо открытия внешних ссылок),
`RUNET_RECHECK_MS`, `RUNET_DIRECT_IP`, `RUNET_EXPECTED_COUNTRY` (проверка остаётся настоящей и отклоняет несовпадение),
`RUNET_TEST_CHROME_URL`, `RUNET_TEST_CHROME_PROMPT` (заранее заданные ответы окна «Нужен Chrome»: `install,pick,open,recheck,close`),
`RUNET_TEST_CHROME_PICK`, `RUNET_TEST_NO_AUTODETECT`, `RUNET_TEST_DIALOG_DUMP`. Окна в тестовом режиме помечены «ТЕСТ».

## Какие ключи принимаются

Формат определяется автоматически (подробно: [KEY-FORMATS.md](KEY-FORMATS.md)):

- `vless://` — Reality поверх TCP с `flow=xtls-rprx-vision` (обязательны `pbk`, `sni`, `flow`) и TLS поверх WebSocket (`type=ws`;
  `sni`, `host`, `path`, `alpn`, `fp` берутся из ключа); проверка сертификата сервера всегда включена: ключи с `allowInsecure=1` отклоняются;
- `ss://` — Shadowsocks (SIP002, старая форма в одном Base64, статические ключи Outline, AEAD-2022);
- `ssconf://` — динамические ключи Outline: настройки (ссылка `ss://`, JSON или YAML в простой документированной форме)
  загружаются при каждом подключении по HTTPS.

Всё остальное (в том числе «префикс» Outline, плагины и чужие транспорты) приложение отклоняет понятным сообщением с названием причины,
не раскрывая ключа.
