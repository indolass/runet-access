## Сценарий, которого в upstream не было

- Принимается только `vless://` + `security=reality` + `flow=xtls-rprx-vision` + TCP; обязательны
  `pbk`, `sni`, корректный UUID. Парсер upstream молча подставляет адрес сервера вместо
  отсутствующего `sni`: такой ключ мы отвергаем. Ошибки не содержат ни части ключа.
- Через прокси идут **только** сайт (+ его поддомены), введённые дополнительные адреса и два
  диагностических адреса; остальной Chrome — напрямую.
- Проверка выхода идёт через тот же маршрут PAC → локальный SOCKS → VLESS, что и сайт.
  Эталон «обычный интернет» (`api.ipify.org`) в список прокси не входит. Вердикты: `ok`,
  `wrong-country`, `same-ip` (трафик идёт мимо прокси), `unknown` (сбой диагностики — не успех).
  При `wrong-country`/`same-ip` подключение автоматически отключается.
