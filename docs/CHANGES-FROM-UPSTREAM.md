# Что взято из MagicProxy baf56b5 и что изменено

Заимствованный код (MIT, уведомление в `third_party/MagicProxy/LICENSE`) лежит в `src/app/internal/`.

## Используется из MagicProxy

| Пакет | Что делает | Изменения |
|---|---|---|
| `internal/config` | Генератор конфига sing-box из профиля (`mixed`-inbound, VLESS/Reality, DNS через туннель) | Без изменений, кроме форматирования `gofmt` и имени модуля |
| `internal/core` | Запуск/остановка sing-box, Job Object `KILL_ON_JOB_CLOSE`, порт, события выхода | См. ниже |

Изменения в `internal/core`:

| Изменение | Зачем |
|---|---|
| Рабочий каталог `%TEMP%\runet-access\host-<pid>` | Не пересекается с настоящим MagicProxy |
| `config.json` с ключом удаляется, как только порт ядра открылся | sing-box читает файл один раз; раньше он лежал на диске всё время работы |
| `Stop()` ждёт фактического завершения ядра (до 3 с) | Иначе при выходе рабочий каталог (cwd ядра) не удалялся и оставался на диске; найдено интеграционным тестом |
| `WaitReady()` | Upstream считал ядро «запущенным» сразу после старта процесса, хотя порт открывается через 0,3–0,6 с; браузер, направленный на порт раньше, получал «connection refused» |

## Не используется (осталось в истории git, коммит `e649846`)

Расширение Chrome (popup, options, onboarding, PAC-режим), native messaging хост, самообновление ядра
(качало sing-box «latest» без проверки хеша), диагностика TUN, установщик Inno Setup, `setup.ps1`.
После уточнения Owner (специальный браузер, весь трафик, без расширений и ручной настройки) они не нужны.

## Новое в runet-access

- `cmd/launcher` — `RunetAccess.exe`: запускает ядро и отдельный Chrome (`--user-data-dir`,
  `--proxy-server=socks5://127.0.0.1:<порт>`, `--host-resolver-rules=MAP * ~NOTFOUND , EXCLUDE 127.0.0.1`,
  `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`, `--disable-background-mode`); локальная
  страница управления (ввод ключа, подключение, проверка выхода, «Открыть сайт», «Отключить»); «страж» порта,
  автоперезапуск ядра, единственный экземпляр, очистка при закрытии окна. Страница доступна только по
  loopback, по случайному токену (cookie), с проверкой `Host` и заголовка `X-Runet`.
- `internal/keyparse` — строгий разбор ключа (`vless` + Reality + `xtls-rprx-vision` + TCP; обязательны `pbk`,
  `sni`, UUID). Парсер upstream молча подставляет адрес сервера вместо отсутствующего `sni`; такой ключ мы
  отвергаем. Ошибки не содержат ни части ключа.
- `internal/dpapi` — хранение ключа, зашифрованного Windows DPAPI (по желанию пользователя).
- Проверка выхода (`ui/check.js`): проба выполняется в самом окне, то есть тем же маршрутом, что и любой сайт;
  эталон «обычное соединение» отдаёт лаунчер (напрямую, без прокси). Вердикты: `ok`, `wrong-country`,
  `same-ip` (трафик идёт мимо ключа), `unknown` (сбой диагностики — не успех). При `wrong-country`/`same-ip`
  подключение автоматически отключается.
