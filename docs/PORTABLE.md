# Переносимая версия (один файл)

`dist\portable\RunetAccess-Portable-<версия>.exe` — одна программа без установки, прав администратора и ручной распаковки: двойной щелчок,
окно Runet Access, вставить свой ключ, подключиться. Собирается `scripts\make-portable.ps1`. Рядом лежат `RunetAccess-Portable-<версия>.sha256.txt`
и «Инструкция-Portable.txt» (исходник — `portable\Instruction-RU.txt`); для друга достаточно этих трёх файлов.

Версия продукта та же (0.5.0), что у установщика: это другой способ упаковки того же лаунчера. Отличается сборка с тегом `portable`
(`go build -tags portable`): в неё встроены sing-box и тексты лицензий.

## Что внутри файла и как это запускается

- Встроенный `payload.zip` (≈ 16 МБ): `sing-box.exe` v1.13.16 (неизменённый официальный выпуск, закреплён хешем), каталог `licenses/`
  (лицензии, перечень Go-библиотек, `BUILD-INFO.txt`, GPL-3.0, письменное предложение на исходный код, архив исходников sing-box) и `MANIFEST.sha256`.
  Итоговый файл ≈ 28 МБ. Chrome в файл **не входит**: используется установленный (существующее обнаружение и «Указать chrome.exe»).
- При каждом запуске (после проверки блокировки «второго экземпляра») программа:
  1. сверяет встроенный zip с SHA-256, вшитым при сборке (`-X main.payloadSHA256`), и список `MANIFEST.sha256` с вшитым хешем ядра
     (`-X main.coreSHA256`);
  2. проверяет `%LOCALAPPDATA%\RunetAccess\components\<первые 16 символов хеша>\`: каждый файл сравнивается с манифестом; всё сошлось — берётся как есть;
  3. иначе распаковывает заново из самого exe во временную папку `.tmp-…`, проверяет и переименованием ставит на место (повреждённая копия
     сначала отодвигается, не правится на месте);
  4. открывает `sing-box.exe` на чтение **без разрешения записи и удаления для других** и держит дескриптор до конца работы, а хеш считает ещё раз
     уже через этот дескриптор: между проверкой и запуском файл подменить нельзя, пока программа работает;
  5. запускает ядро из этой копии (`core.NewManagerAt`); остальное — как в установленной версии (отдельный Chrome с прокси на порт ядра,
     «сторож» порта, проверка RU, fail-closed, Job Object, DPAPI).
- Папка по хешу означает, что **новая версия exe распаковывается в другую папку**: работающий экземпляр старой версии (его ядро занято и
  заблокировано) обновлением не затрагивается. Лишние папки сборок и остатки `.tmp-`/`.old-` убираются, чужие папки не трогаются.
- Рядом с exe ничего не пишется (папка может быть только для чтения), ярлыки, автозапуск, службы, записи об установке, системный прокси и TUN не используются.
  Реестр программа только читает (поиск Chrome); записей не делает.
- `RunetAccess-Portable-<версия>.exe --licenses` открывает папку с распакованными лицензиями и архивом исходников sing-box (работает и при запущенной программе).

Нельзя сказать «подмена невозможна»: процесс того же пользователя с правами записи в `%LOCALAPPDATA%` может, например, остановить программу и подменить
exe до запуска. Защита здесь — от случайного повреждения, от незаметной подмены распакованных файлов между запусками и во время работы.

## Где остаются данные (одним файлом они всё равно создаются)

`%LOCALAPPDATA%\RunetAccess` (то же хранилище, что у установщика, данные установленной версии не затрагиваются):

| Запись | Что это |
|---|---|
| `components\<хеш>\` | распакованные sing-box и лицензии (создаётся и проверяется программой) |
| `profile\` | отдельный профиль окна Chrome |
| `key.dpapi` | сохранённый ключ, только если пользователь не снял «Запомнить на этом компьютере»; зашифрован DPAPI |
| `run.lock`, `chrome-path.txt` | блокировка второго экземпляра; путь к `chrome.exe`, если его указали вручную |

Убрать всё: закрыть программу, удалить exe и эту папку. Установленная версия и переносимая делят одну папку данных и один замок «одного экземпляра»:
вместе они запущены быть не могут, ключ и профиль общие.

## Сборка и проверка

```powershell
. .\scripts\env.ps1
.\scripts\make-portable.ps1          # обычная сборка + проверки + payload + exe + sha256 + инструкция
.\tests\run-hidden.ps1 tests\portable-check.ps1                  # упаковка (13 проверок)
$env:RUNET_EXE = "$PWD\dist\portable\RunetAccess-Portable-0.5.0.exe"
.\tests\run-hidden.ps1 tests\keyformats-check.ps1                # форматы ключей через новую упаковку
.\tests\run-hidden.ps1 tests\prefix-check.ps1                    # prefix через новую упаковку
```

`make-portable.ps1` останавливается, если sing-box не совпал с закреплённым выпуском, файлы payload не совпали с явным списком, найден материал
ключа Owner или личные пути (в payload и в итоговом exe; значения не печатаются). Сгенерированный `payload.zip` лежит в
`src\app\cmd\launcher\payload\` (в Git не попадает) и после сборки удаляется.
