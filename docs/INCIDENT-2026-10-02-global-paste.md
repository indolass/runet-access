# Инцидент 2026-10-02: глобальная вставка ключа при проверке через v2rayN

**Статус: факт утечки НЕ установлен. Отсутствие утечки тоже НЕ доказано.**

## Что произошло

При контрольном сравнении ключа с готовым клиентом (v2rayN) ранняя версия скрипта
`tests/real-v2rayn-compare.ps1` (в Git не попадала; закоммичена только исправленная) делала следующее:

1. клала ключ в **системный буфер обмена**;
2. пыталась вывести окно v2rayN на передний план (`SetForegroundWindow`) и **не проверяла результат**;
3. отправляла **глобальные нажатия клавиш**: Ctrl+V, затем «Вниз» и Enter (`SendKeys`).

Глобальные нажатия получает то окно, у которого в этот момент фокус. Если фокус был не у v2rayN, ключ мог быть
вставлен в другое окно (поле чата, браузер, редактор), а Enter мог его отправить.

Скрипт с этим поведением до конца отработал как минимум один раз (вечер 2026-10-02). Был ещё запуск, который
завис; отправлял ли он клавиши, неизвестно. Дата и время запусков в отчёте приблизительные.

## Что установлено, а что нет

| | |
|---|---|
| Установлено | Скрипт отправлял Ctrl+V / «Вниз» / Enter без проверки активного окна; ключ в это время лежал в буфере обмена |
| Не установлено | Получил ли v2rayN вставку в тех запусках. Осталась ли вставка в каком-либо другом окне. Отправлялось ли что-то Enter-ом куда-либо |
| Проверка Git | Ничего не доказывает: Git содержит только файлы репозитория. Ключ мог попасть за его пределы. В репозитории ключа нет (проверено поиском), но это не отвечает на вопрос об утечке |
| Сам ключ в моей части переписки | Не появлялся. Это не доказывает, что он не мог быть вставлен в другое окно или приложение |
| История буфера обмена Windows | Параметр `EnableClipboardHistory` в реестре текущего пользователя не задан (читалось без изменений); обычно это означает «выключена». Сторонние менеджеры буфера обмена и облачная синхронизация не проверялись |

## Что сделано после

- Глобальная автоматизация ввода убрана полностью. Нынешняя версия скрипта не отправляет ни клавиш, ни мыши:
  импорт делается штатным пунктом меню v2rayN через UI Automation, сервер активируется записью идентификатора в
  конфиг копии (идентификаторы читает `tests/dbget.mjs`, только `IndexId` и тип), без ввода.
- В последующих запусках (UI Automation) ключ всё равно кратко (несколько секунд, около пяти запусков) лежал в
  буфере обмена, после чего прежнее содержимое восстанавливалось. Это отдельный канал воздействия, он описан в
  заголовке скрипта: запускать только с согласия владельца.
- Новых запусков с этим сервером и новой автоматизации GUI после этого не делалось.

## Рекомендации владельцу (решения принимает владелец)

1. Просмотреть места, где мог быть фокус в момент проверки: поле ввода чата, браузер, редакторы. Искать посторонний
   текст `vless://...`. Проверить историю буфера обмена Win+V и менеджеры буфера обмена, при необходимости очистить.
2. Если исключить вставку нельзя, считать ключ **потенциально раскрытым** и попросить оператора заменить его.
   Сервер сейчас всё равно отвергает соединение, поэтому замена стоит немногого.

## Уроки для проекта

- Никакого глобального ввода (клавиатура, мышь) в автоматизации, особенно когда в буфере или поле лежит секрет.
- Если ввод всё-таки необходим, сначала подтверждать, что целевое окно активно, и посылать только безопасные данные.
- Секреты не класть в буфер обмена; если иначе нельзя, согласовать это заранее и ограничить время.
