Прототип **не plug-and-play**: установка человеком без технических навыков не проверялась,
а доставка расширения в Chrome требует ручного шага (ниже).

## Препятствия

1. **Ручная установка расширения (блокирует «plug-and-play»).** Сейчас: режим разработчика →
   «Загрузить распакованное». Chrome 137+ игнорирует `--load-extension`; принудительная установка
   политиками из своей папки, по документации Chrome, работает только на управляемых компьютерах (не проверялось). Ожидаемо Chrome будет при каждом
   запуске предупреждать о расширениях режима разработчика (на реальном профиле **не проверялось**:
   тесты грузили расширение через отладочный канал). Рабочий путь для конечного пользователя —
   отдельная публикация в Chrome Web Store: свой листинг, свой ключ и ID, добавить ID в
   `allowed_origins` (`scripts\build.ps1`), проверка магазина. Не сделано.
2. **SmartScreen и антивирусы.** `runet-access-host.exe` и `sing-box.exe` не подписаны; архив,
   скачанный из интернета, получает пометку «из интернета», и Windows может предупредить при запуске
   `Install.cmd`. Антивирусы нередко ругаются на прокси-ядра на Go. Подпись кода требует платного
   сертификата. `.exe`-установщик не собирался (не требовался). **NOT TESTED** на чистой Windows.
3. **Электронная подпись.** Плагин подписи (например, КриптоПро) работает через собственный
   native messaging и не зависит от прокси, но должен стоять в том же профиле Chrome, где идёт
   работа, а сайт может требовать ГОСТ-шифрование или конкретную версию браузера. Совместимость
   не проверялась и не может быть проверена без вашего сайта и подписи.
4. **Блокировка IP самим госсайтом.** Приложение лишь показывает, отвечает ли сайт на уровне
   соединения (не читает HTTP-статус и страницу). Сайт может отдать «доступ запрещён» на адрес
   конкретного сервера; это видно только при ручной проверке. Российский сервер и ключ предоставляет
   оператор; приложение их не создаёт и не гарантирует.
5. **Маршрутизация только по доменам.** Через сервер идёт лишь то, что вы перечислили. Если вход или
   статика сайта живут на других доменах (единый вход, CDN), их нужно добавить в «Дополнительные адреса»,
   иначе часть страницы пойдёт напрямую или сломается. Точная цепочка для вашего сайта неизвестна.
6. **Хранение секрета.** Ключ лежит в `chrome.storage.local` открытым текстом (кнопка «Удалить»).
   Пока подключение включено, локальный порт прокси на `127.0.0.1` доступен любой программе этого
   компьютера без пароля (Chrome не умеет аутентификацию SOCKS5). Рабочий каталог хоста находится в
   `%TEMP%` Chrome (вне корня проекта; для тестов он перенаправлялся внутрь), `config.json` с ключом
   удаляется сразу после старта ядра, при жёстком падении остаётся пустой каталог до очистки.
7. **Подключение остаётся включённым между запусками Chrome**, пока вы не нажмёте «Отключить»
   (наследие upstream: намерение хранится и восстанавливается). Прокси применяется только к списку
   доменов, но это стоит знать.
8. **Диагностические сервисы третьих лиц.** `api.country.is` и `ipwho.is` (через туннель) видят IP
   выхода; `api.ipify.org` (напрямую) видит ваш обычный IP. Доступность этих сервисов не гарантирована;
   при сбое результат «не определено», а не «подключено».
9. **Область проверки.** Только Chrome 154 на одной машине; другие браузеры не регистрируются.
   Другое расширение, управляющее прокси, мешает: это обнаруживается и показывается, но не лечится.
   WebRTC-защита в режиме «по доменам» не включается (см. CHANGES-FROM-UPSTREAM.md).
10. **Обновления.** Автообновления нет (самообновление ядра отключено). Версии закреплены;
    обновление — новой сборкой.
11. **Проверка upstream.** `vendor-bin/magicproxy-host.exe~` в репозитории MagicProxy остаётся
    непроверенным бинарником (не запускался). Аудит безопасности upstream не проводился; проверено только
    перечисленное в [UPSTREAM-REVIEW.md](UPSTREAM-REVIEW.md).

## Расхождение с уточнением Owner от 2026-10-02 (AGENTS.md / PLAN.md, `267ee01`)

Прототип собирался до этого уточнения и **ему не соответствует** в двух местах:

1. **Режим маршрутизации.** Сейчас по умолчанию «только перечисленные домены» (PAC). Owner требует базовый
   режим «весь веб-трафик отдельного рабочего профиля», без списков доменов; PAC — позже, как дополнение.
2. **Доставка.** Сейчас это расширение, которое вручную ставится в Chrome. Owner требует специальный
   браузер (отдельный ярлык, профиль создаётся приложением, без режима разработчика и ручной настройки).

Переиспользуется без изменений: хост + sing-box (запуск, готовность порта, остановка, очистка конфига),
строгая проверка ключа, логика проверки выхода, fail-closed тесты, скрипты сборки.
Нужно изменить: режим «весь трафик» (в нём «обычный интернет» невозможно проверить изнутри браузера,
эталонный прямой IP должен получать сам хост) и способ запуска. Chrome 137+ не грузит расширения
флагом `--load-extension`, поэтому для поставки без режима разработчика есть два пути:
(A) расширение в отдельном профиле остаётся, но тогда нужен Chrome Web Store;
(B) расширение не нужно вовсе: лаунчер сам запускает ядро и Chrome с отдельным `--user-data-dir` и
`--proxy-server=socks5://127.0.0.1:<порт>` (весь трафик этого окна через ядро, мёртвый порт даёт ошибку, а не
прямой выход, реестр и native messaging не нужны). Для (B) нужен небольшой интерфейс ввода ключа и статуса.
Выбор не сделан.
