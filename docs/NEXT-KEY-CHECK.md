# Сценарий проверки следующего ключа

Готов к использованию; запускать, когда владелец сообщит, что ключ заменён. Реальный ключ вводит только владелец,
в `.local\secrets\test-key.txt` (одна строка `vless://...`; имя после `#` может содержать пробелы).

## Жёсткие правила

- Ключ не печатать, не вставлять в команды, логи, скриншоты, чат и Git. Файл ключа **не удалять** и не менять.
- Не просить ключ в чате. IP в отчётах маскировать (первый октет), адрес сервера не показывать.
- Останавливать только процессы, запущенные мной. Обычный браузер и системный прокси не трогать.
- Не менять архитектуру и не добавлять функции до завершения проверки.
- Никакого глобального ввода (клавиатура, мышь) и никакой новой GUI-автоматизации без отдельного согласия.
- Рабочие файлы только внутри `D:\AI-workspaces\runet-access`.

## Положительный контроль без ключа владельца

Если ключ владельца недоступен или нужно убедиться, что код и это соединение исправны, есть готовый контроль на
публичных серверах (Xray + наш код + браузер): [POSITIVE-CONTROL.md](POSITIVE-CONTROL.md). Он не заменяет проверку
российского выхода и госсайтов.

## Шаги

1. **Сравнить сервер со старым, ничего не печатая.**
   `node tests\real-compare-server.mjs compare`
   - код выхода 3 и «ДА»: сервер тот же, что отвергал соединение. Предупредить владельца и **не** проверять повторно.
   - «нет»: идти дальше.
2. **Подключение, российский выход, три публичные страницы** (Госуслуги, ФНС, Минюст):
   `. .\scripts\env.ps1; node tests\real-check.mjs`
   Скрипт ждёт файл, подключается в нашем специальном браузере, проверяет страну выхода, открывает страницы и
   печатает таблицу «сайт → открылся ли → капча → ошибка». Файл ключа остаётся на месте.
3. **Если подключение не удалось, установить слой причины** (по порядку):
   - `node tests\real-dns-check.mjs`: DNS одинаков ли у разных резолверов, TCP до каждого адреса;
   - `node tests\real-diagnose.mjs`: DNS → TCP → «голый» sing-box с журналом → трафик через него.
   Различать: ключ/сервер; транспорт (Reality); проверка страны; конкретный сайт.
4. **Независимый клиент (только по отдельной команде владельца).**
   `powershell -NoProfile -ExecutionPolicy Bypass -File tests\real-v2rayn-compare.ps1`
   Работает на копии v2rayN (7.25.4, источник `D:\soft\v2rayN-windows-64`), системный прокси «не менять», TUN выключен,
   запрос идёт явно через локальный прокси v2rayN. Ввода не отправляет, но **кладёт ключ в буфер обмена на несколько
   секунд** (см. `INCIDENT-2026-10-02-global-paste.md`): нужно согласие владельца на эту экспозицию.
5. **После успешного нового ключа** владелец подтверждает, и тогда `node tests\real-compare-server.mjs save`
   запоминает отпечаток нового сервера.

## Критерии

- Сайт пройден, если публичная страница **отобразилась в браузере** с видимым содержимым, без капчи, антибот-проверки
  и отказа в доступе. HTTP 200 недостаточно.
- Капча: не решать и не обходить. Фиксировать «Критерий не пройден: капча».
- Отдельно отмечать: таймаут, ошибку соединения, отказ сайта.
- Отказ по стране выхода — не ошибка соединения.
- Разделять: установление туннеля, загрузка страницы, страна выхода.

## Не входит

Вход в аккаунты, электронная подпись, отправка отчётов — выполняет владелец.
Результаты по сайтам вносить в [COMPATIBILITY.md](COMPATIBILITY.md) (без персональных данных).

## Дополнение 2026-10-03 (второй ключ HLVPN)

- Слойная проверка ключа из файла одной командой: `. .\scripts\env.ps1; node tests\owner-key-check.mjs --now`
  (без `--now` ждёт изменения файла). Сравнивает независимый Xray и наш путь, называет слой отказа только по журналу.
  Умеет Reality/TCP и TLS/WebSocket. Совпадение сервера со старым ключом уже не запрещает один контрольный запуск.
- Диагностика медленной или «пустой» публичной страницы: `node tests\real-page-diag.mjs https://...` (сеть, статусы по
  хостам, сбои загрузки, рост видимого текста, видимые элементы капчи).
- Вердикт «страница открылась / капча / отказ» ведёт `tests\page-verdict.mjs`: капча только если она видна, а страница,
  которая ещё рисуется, не считается ни блокировкой, ни успехом. SPA (Госуслуги) могут рисоваться 30–60 с.
- Если ключ другого вида (не Reality/TCP и не TLS/WebSocket), сначала проверить его в независимом Xray и только потом
  расширять парсер, не ослабляя проверку сертификата.

## Дополнение 2026-10-06 (Outline `ssconf://` с префиксом, версия 0.5.0)

Настоящий ключ Outline (работоспособность в официальном клиенте Outline подтвердил владелец; нашей проверкой это не является) кладётся
владельцем **одной строкой** в `.local\secrets\ssconf-key.txt`. Файл не читается ни в какие логи и не удаляется скриптами. Проверка:

```powershell
. .\scripts\env.ps1; $env:RUNET_KEY_FILE = '.local\secrets\ssconf-key.txt'; node tests\real-check.mjs
```

Скрипт открывает наше специальное окно (видимое), вставляет ключ через страницу управления (не клавиатурой), ждёт подключения, показывает
страну выхода и по очереди открывает публичные страницы Госуслуг, ФНС и Минюста: «сайт → отобразился ли → видимая капча/антибот → ошибка».
Если не подключилось, сообщение приложения называет слой: загрузка настроек, формат/параметры (например, шифр, не поддержанный с префиксом,
или YAML другой формы), сервер, страна выхода.
